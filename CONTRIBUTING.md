# Contribuindo

1. Leia os [padrões de engenharia](docs/engineering/), o [guia editorial](docs/STYLE_GUIDE.md) e a [documentação pública](docs/README.md).
2. Trabalhe em uma branch ou worktree isolada.
3. Faça uma mudança pequena, com teste e documentação quando aplicável.
4. Execute os gates do projeto antes do pull request.
5. Descreva limitações e evidências; não declare suporte nativo sem runner correspondente.

Use Conventional Commits. Para vulnerabilidades, siga [SECURITY.md](SECURITY.md) em vez de abrir issue pública.
